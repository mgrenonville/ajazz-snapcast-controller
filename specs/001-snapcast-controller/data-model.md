# Data Model: Snapcast Controller Application

**Date**: 2025-12-12
**Feature**: 001-snapcast-controller

## Overview

This document defines the data structures used by the Snapcast controller application to manage state, configuration, and communication between the hardware controller and Snapcast server.

## Core Entities

### 1. ConnectionSettings

**Purpose**: Persistent configuration for server connectivity and room assignment

**Fields**:
- `server_address`: String - IP address or hostname of Snapcast server
- `server_port`: u16 - TCP port for JSON-RPC API (typically 1705)
- `room_client_id`: String - Snapcast client ID this controller manages (e.g., "living-room")
- `auth_credentials`: Option<AuthCredentials> - Optional authentication (future)

**Validation Rules**:
- `server_address` must be valid IP or resolvable hostname
- `server_port` must be in range 1-65535
- `room_client_id` must be non-empty string

**Storage**: Persisted in `~/.config/snapcast-controller/config.toml`

**Rust Type Sketch**:
```rust
#[derive(Debug, Deserialize, Serialize)]
struct ConnectionSettings {
    server_address: String,
    server_port: u16,
    room_client_id: String,
}
```

---

### 2. RoomState (Audio Client)

**Purpose**: Runtime state of the room being controlled

**Fields**:
- `client_id`: String - Unique identifier for this room's client
- `name`: String - Human-readable name ("Living Room")
- `volume`: u8 - Volume level 0-100
- `muted`: bool - Mute status
- `connected`: bool - Whether client is connected to server
- `stream_id`: Option<String> - Currently assigned stream ID
- `latency`: Option<u32> - Audio latency in milliseconds (informational)

**State Transitions**:
- `connected`: false → true (when client appears in Server.GetStatus)
- `connected`: true → false (when client disappears or server disconnects)
- `volume`: Updated via hardware knob or server notification
- `muted`: Toggled via hardware button or server notification
- `stream_id`: Changed via hardware button (stream selection) or server notification

**Validation Rules**:
- `volume` must be 0-100 range
- Changes must be reflected on hardware screens within 2 seconds

**Rust Type Sketch**:
```rust
#[derive(Debug, Clone)]
struct RoomState {
    client_id: String,
    name: String,
    volume: u8,      // 0-100
    muted: bool,
    connected: bool,
    stream_id: Option<String>,
    latency: Option<u32>,
}
```

---

### 3. AudioStream

**Purpose**: Represents an audio source available on the Snapcast server

**Fields**:
- `stream_id`: String - Unique stream identifier
- `name`: String - Display name ("Spotify", "Radio", "Aux Input")
- `status`: StreamStatus - Playing, Idle, or Unknown
- `metadata`: Option<StreamMetadata> - Current track info (if available)

**Stream Status Values**:
- `Playing`: Stream is actively playing audio
- `Idle`: Stream exists but no audio
- `Unknown`: Status cannot be determined

**Metadata** (optional):
- `artist`: Option<String>
- `title`: Option<String>
- `album`: Option<String>

**Rust Type Sketch**:
```rust
#[derive(Debug, Clone)]
struct AudioStream {
    stream_id: String,
    name: String,
    status: StreamStatus,
    metadata: Option<StreamMetadata>,
}

#[derive(Debug, Clone)]
enum StreamStatus {
    Playing,
    Idle,
    Unknown,
}

#[derive(Debug, Clone)]
struct StreamMetadata {
    artist: Option<String>,
    title: Option<String>,
    album: Option<String>,
}
```

### 4. HardwareEvent

**Purpose**: Events generated by the USB HID hardware controller

**Event Types**:
- `KnobRotated { knob_id: u8, delta: i8 }` - Knob turned (positive = clockwise)
- `ButtonPressed { button_id: u8 }` - Button pressed down
- `ButtonReleased { button_id: u8 }` - Button released
- `PageButtonPressed { page_id: u8 }` - Page navigation button pressed
- `DeviceConnected` - Hardware controller plugged in
- `DeviceDisconnected` - Hardware controller unplugged

**Knob IDs**: 0, 1, 2 (3 knobs total)
**Button IDs**: 0-5 (6 buttons with screens)
**Page IDs**: 0-2 (3 page buttons)

**Rust Type Sketch**:
```rust
#[derive(Debug, Clone)]
enum HardwareEvent {
    KnobRotated { knob_id: u8, delta: i8 },
    ButtonPressed { button_id: u8 },
    ButtonReleased { button_id: u8 },
    PageButtonPressed { page_id: u8 },
    DeviceConnected,
    DeviceDisconnected,
}
```

---

### 5. SnapcastEvent

**Purpose**: Events received from Snapcast server

**Event Types**:
- `ClientVolumeChanged { client_id: String, volume: u8, muted: bool }` - Volume or mute changed
- `ClientConnected { client_id: String }` - Client came online
- `ClientDisconnected { client_id: String }` - Client went offline
- `StreamChanged { client_id: String, stream_id: String }` - Client assigned to different stream
- `ServerDisconnected` - Lost connection to server
- `ServerReconnected` - Connection restored

**Rust Type Sketch**:
```rust
#[derive(Debug, Clone)]
enum SnapcastEvent {
    ClientVolumeChanged { client_id: String, volume: u8, muted: bool },
    ClientConnected { client_id: String },
    ClientDisconnected { client_id: String },
    StreamChanged { client_id: String, stream_id: String },
    ServerDisconnected,
    ServerReconnected,
}
```

---

### 6. ControllerCommand

**Purpose**: Commands sent from controller to Snapcast server

**Command Types**:
- `SetVolume { client_id: String, volume: u8 }` - Adjust volume
- `SetMute { client_id: String, muted: bool }` - Mute or unmute
- `AssignStream { client_id: String, stream_id: String }` - Change stream
- `GetStatus` - Request full server status

**Validation**:
- `volume` must be 0-100
- `client_id` and `stream_id` must be non-empty

**Rust Type Sketch**:
```rust
#[derive(Debug, Clone)]
enum ControllerCommand {
    SetVolume { client_id: String, volume: u8 },
    SetMute { client_id: String, muted: bool },
    AssignStream { client_id: String, stream_id: String },
    GetStatus,
}
```

---

### 7. ApplicationState

**Purpose**: Central state machine for the application

**Fields**:
- `config`: ConnectionSettings - Loaded from config file
- `room`: Option<RoomState> - Current room state (None if disconnected)
- `streams`: Vec<AudioStream> - Available streams on server
- `hardware_connected`: bool - USB controller connection status
- `server_connected`: bool - Snapcast server connection status
- `selected_stream_index`: usize - UI state for stream selection
- `current_page`: PageView - Which page is displayed on hardware

**Page Views**:
- `Status`: Show room volume, mute status, current stream
- `StreamSelection`: Show list of available streams for selection
- `Settings`: Show connection status, server address (future)

**State Invariants**:
- If `server_connected == false`, then `room` must be `None`
- `selected_stream_index` must be < `streams.len()`
- Screen updates must reflect state changes within 2 seconds

**Rust Type Sketch**:
```rust
#[derive(Debug)]
struct ApplicationState {
    config: ConnectionSettings,
    room: Option<RoomState>,
    streams: Vec<AudioStream>,
    hardware_connected: bool,
    server_connected: bool,
    selected_stream_index: usize,
    current_page: PageView,
}

#[derive(Debug, Clone, Copy)]
enum PageView {
    Status,
    StreamSelection,
    Settings,
}
```

## Data Flow

### Initialization
1. Load `ConnectionSettings` from TOML file
2. Initialize `ApplicationState` with config
3. Wait for `HardwareEvent::DeviceConnected`
4. Connect to Snapcast server using config
5. Send `GetStatus` command to populate `room` and `streams`

### Volume Control Flow
1. User rotates knob → `HardwareEvent::KnobRotated { delta: +5 }`
2. Controller updates `room.volume` (clamped 0-100)
3. Controller sends `ControllerCommand::SetVolume` to server
4. Server acknowledges and broadcasts `SnapcastEvent::ClientVolumeChanged`
5. Controller updates hardware screen to show new volume

### Stream Selection Flow
1. User presses page button → Switch to `PageView::StreamSelection`
2. Hardware screens show stream list (buttons 0-5 = streams 0-5)
3. User presses button 2 → Select `streams[2]`
4. Controller sends `ControllerCommand::AssignStream` to server
5. Server broadcasts `SnapcastEvent::StreamChanged`
6. Controller updates `room.stream_id` and switches to `PageView::Status`

### Reconnection Flow (Hardware)
1. `HardwareEvent::DeviceDisconnected` received
2. Set `hardware_connected = false`
3. Wait for `HardwareEvent::DeviceConnected`
4. Restore previous page view and refresh screens

### Reconnection Flow (Server)
1. `SnapcastEvent::ServerDisconnected` received
2. Set `server_connected = false`, `room = None`
3. Display "Connecting..." on hardware screens
4. Retry connection with exponential backoff
5. On success: `ServerReconnected`, send `GetStatus`, restore state

## Persistence Strategy

**What is persisted**:
- `ConnectionSettings` (server address, port, room ID) → `config.toml`

**What is NOT persisted**:
- `RoomState` - Rebuilt from server on connect
- `AudioStream` list - Fetched from server
- UI state (selected stream, page view) - Defaults to Status page on startup
- Hardware connection status - Detected at runtime

**Rationale**: Simplicity First principle - persist only configuration that cannot be derived from runtime state.

## Error Handling

**Validation Failures**:
- Invalid config file → Display error on hardware screen, use defaults, allow user to reconfigure
- Invalid volume value → Clamp to 0-100 range
- Unknown client ID → Display "Room not found" error, allow user to reconfigure

**Network Failures**:
- Server unreachable → Retry with backoff, display connection status
- Command timeout → Retry once, display error if still failing

**Hardware Failures**:
- Device disconnect during operation → Save state, wait for reconnect
- Screen update failure → Log error, continue operation (don't crash)
